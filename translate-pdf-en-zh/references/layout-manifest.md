# 布局 JSON

脚本只做文件/版面操作，模型负责翻译、选字体、视觉检查和复杂版面定制。需要 Python 3.10+、`PyMuPDF>=1.26,<2`，没有远程 API 或密钥。

`extract` 生成 `source_sha256` 和 `pages`。每页含 `page`、`width`、`height`、`image_rects`、`needs_visual_review`、`blocks`。块含固定 `id`、`source`、`bbox`、`lines`（含字体/颜色/大小/方向），以及待填写的 `action`、`zh`。

在提取文件上填写，不重新手写整份 JSON。保留原始字段，仅编辑：

| 字段 | 用途 |
| --- | --- |
| `action` | 必填：`translate` 或 `keep` |
| `zh` | `translate` 必填完整译文 |
| `reason` | `keep` 必填语义保留原因 |
| `font_file` | 可选，覆盖命令行默认字体，按原文风格选择 |
| `align` | 0 左、1 中、2 右、3 两端；默认 0，需看原图判定 |
| `lineheight` | 默认 1.2，按原稿调整，不以挤压换取容纳 |
| `target_bbox` | 默认原 bbox；仅在确认空白后微调，不越界或盖住相邻块 |

例：在某块中填入 `"action": "translate", "zh": "实验结果显示，该方法提高了测量精度。", "font_file": "C:/Windows/Fonts/simsun.ttc", "align": 0`，其余原始字段不动。

`apply` 核对源文件哈希及原始块，防止误用另一个版本。每块必须处理，但它不理解 `keep` 理由是否合理，也不能证明图片内部无英文，仍需模型复核。

仅支持横排、单字体/字号/颜色的独立文本块。字号尝试范围为原字号的 90%–100%，低于 8pt 不再缩小。文本框太矮、混合样式、字体缺字、与图片相交、潜在邻块误删等会报错，不通过篡改原字段绕过，改用局部定制排版。

`pair --gap 0` 默认无间隙，间隙单位 pt、颜色白。左侧渲染比对在 96 DPI 进行，平均通道差阈值为 0.5/255，用于发现可见对象丢失及旋转/尺寸错误，不是印刷级逐像素证明。各命令拒绝覆盖已有输出，用新文件名迭代。
